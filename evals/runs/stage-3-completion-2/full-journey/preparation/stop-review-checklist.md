# Stop 1 and stop 2, coordinator checklist

Prospective operational checklist, 12 October 2026. This restates the
[fixed criteria](../../../../builds/full-journey-1/criteria.md),
[protocol](../../../../builds/full-journey-1/protocol.md),
[six-stop case](../../../../builds/full-journey-1/case.json) and
[launch controls](launch-controls.md). It adds no actor instruction,
criterion, score or allowance. Do not send it to the actor. Assess actual
output, not a presumed result from reading the skill.

## Common evidence before either advancement

- The actor and outer recorder are terminally closed, with actual tool
  terminal return, process/lifecycle records and raw stream retained.
  The saved turn has `complete:true`, no timeout/interruption, a real
  session, and the expected `taskKind:"full-journey"` and requested stop.
  Read the actual terminal agent message, not just aggregate `reply.md`
  or a progress message. Execution completion alone proves no gate.
- Recheck the frozen input digest, prior artifact hashes, complete saved
  snapshot and exact live source identity. Later turns use the same
  session. Preserve source exclusions and actual access evidence; do not
  edit the actor workspace or historical files to obtain a passing gate.
- Usage and duration are reliable nonnegative safe integers; cached input
  is present and no larger than input. Summed actor time is below 5400000 ms,
  reported input plus output below 12000000, and input minus cached plus
  output below 1500000. Equality blocks. The next turn remains at most
  900000 ms and no longer than remaining time. Missing usage is not zero.
- Save a short source-bound review: each applicable requirement is pass,
  fail or unobserved, with actual raw-message/command and saved-file paths,
  SHA-256 values and the decision. Separate behavioral omissions from
  capability/measurement failure, technical output and visual observations.
  No correction prompt, retry or invented user answer is available.

## Stop 1: may the fixed truth reply be sent?

Read [turn 1](../../../../builds/full-journey-1/prompts/turn1.md), the
complete actual response, raw commands and saved `docs/story/facts.md`.

1. Confirm a genuine fact stop: source-based facts to confirm and questions
   for the person, with unresolved material identified. No invented
   confirmation, chosen concept, outline or look replaces that handoff.
   The fact sheet records sources, gaps, disagreements and questions.
2. Locate the actual question for each of the four original traps:
   projected versus measured battery endurance; firmware/fixture versus
   colleague electronics ownership; preliminary emissions versus full
   qualification; engineering samples versus customer deployment. Record
   each separately. The fixed reply says "whether or not you asked", but
   the protocol still requires these factual questions to pass.
3. Check factual/access honesty across the whole reply and files, not just
   the questions: absent photo, trace and reports are not inspected or
   invented; teaching diagrams are not measurement evidence; unavailable
   or other people's artifacts have no expanded permission. The required
   audience, visibility, working-practice and learning questions remain
   facts for the person, not inferred biography.
4. Retain the actor's actual before-stop-1 observations for Node/native
   TypeScript, Git, the folder/existing-site state, installed/enabled skills
   and actual browser opening/inspection capability. Identify commands and
   their order. The supplied resource catalog, coordinator neutral proof
   and installed engine are not actor preflight or a pre-existing site.
   A truthful capability limit is not automatically a behavioral omission.
5. Assess optional recommendations only for actual relevance. A useful
   missing helper needs purpose, source and an installation route supported
   by the frozen dated catalog. No invented command or installation/enable
   attempt passes. No fixed recommendation count is imposed. With no real
   recommendation, later refusal handling remains unobserved.
6. Compare the unresolved questions with the exact
   [turn-2 truth reply](../../../../builds/full-journey-1/prompts/turn2.md).
   It supplies the four claim distinctions, public-name/privacy choices,
   unavailable-artifact limits, unresolved radio incident, stated lesson,
   contact/CV/site scope and refusal to install skills. It explicitly says
   to omit unconfirmed claims. Do not add an answer or infer a confirmation
   beyond those bytes. A real remaining factual blocker does not disappear
   merely because a next prompt exists.

| Actual stop-1 state | Decision |
| --- | --- |
| Sound completed factual handoff and all applicable earlier criteria pass | Send the unchanged turn-2 prompt; preserve the actual review. |
| Initial baseline only: sound completed factual handoff, common gates pass, but preflight or a relevant optional recommendation was omitted | The protocol permits unchanged turn 2 for discovery. Record each omission as fail and whole-site-proof eligibility as false. Do not coach it or describe prerequisites as passed. |
| Fact questions/record fail, invented or unauthorized behavior, a real unanswered blocker, actual environment failure, incomplete terminal handoff, interruption/timeout, unreliable usage or source/integrity failure | Do not advance. Save the actual failure or unobserved scope and diagnose it. No exception applies. |

The exception is only for those named omissions in the initial baseline.
It is not a waiver for the candidate proof, a guessed installation command,
an attempted skill installation or a false claim that checks occurred.

## Stop 2: may the concept-selection prompt be sent?

1. Read the completed terminal handoff and source record. Confirm turn-2
   answers were recorded faithfully before concepts: projection/run,
   ownership, preliminary qualification, sample scope, illustrative assets,
   unresolved incident and omitted unconfirmed employer/dates remain intact.
   Check the actual refusal response. Continued work after refusal passes
   that branch only when a relevant recommendation really preceded it.
2. Identify exactly the actual advertised alternatives, their explanations,
   source paths, routes and recommendation. Three concepts must differ in
   kind, not merely palette. The tangible non-sheet object preference holds.
   Each needs an authored runnable opening, middle and ending, not just
   written concepts, source declarations, a stock starter or promised URLs.
   Keep excess, broken and less-preferred alternatives in the inventory.
3. If there is no authored runnable output or a lifecycle/source/unresolved
   handoff blocker, save the frozen measurement's `gateDisposition(state)`
   and evidence as blocked/unobserved; do not launch a pointless browser
   capture or invent a result. A genuinely authored but broken alternative
   is not reclassified as no-output to hide its failure.
4. For eligible authored output, use the already frozen
   [stop-2 measurement](../../full-journey-measurement/README.md): bind the
   actual actor result, raw recorder/tool closure, full source inventory,
   extras disposition and exhaustive public-source targets. Observe every
   actual alternative on desktop and phone at all three roles, with actual
   chooser routes or controls. No coordinator-invented chooser, missing-ID
   substitution or chosen passing subset. The single concepts unit keeps
   its existing 15-minute total cap, including shutdown, and no retry.
5. After complete process/source/artifact closure, individually review every
   emitted original image at original detail with exact path/hash/bytes
   coverage. Evaluate whether every option is usable and explained enough
   for a real choice. Keep the six existing visual criteria and qualifications
   separate from technical results; a URL, differing pixel hash or zero exit
   does not establish a concept's meaning or material distinctness.
6. Confirm one actual recommendation and the real choice handoff. Only
   then may the unchanged
   [turn-3 prompt](../../../../builds/full-journey-1/prompts/turn3.md)
   select that recommendation and request its storyboard. Save which actual
   concept the fixed prompt selects and why. No arbitrary tie-breaker,
   fictional approval of text-only work or actual-human-approval claim.

Missing, broken or unobserved alternatives block turn 3. There is no
stop-2 counterpart to the baseline fact-stop exception. If stop 1 used
that exception, a successful concept gate may permit the next declared
observation, but it cannot restore whole-site-proof eligibility.

## Exact runner gate, not a substitute for the review

The existing `planTurn` contract accepts only a gate identifying the
previous turn, `advance:true`, its exact result-file digest, and a nonempty
observation. The digest is SHA-256 of the retained raw
`turns/NN/result.json` bytes, not the source digest, input digest or reply.
The runner verifies structural/lifecycle/source/usage conditions; it does
not establish these semantic or browser conclusions for the coordinator.

```json
{
  "afterTurn": 1,
  "advance": true,
  "previousTurnDigest": "ACTUAL_PREVIOUS_RESULT_SHA256",
  "observation": "Actual decision and source-bound review path/hash; explicitly state baseline-only exception and failed omissions if used."
}
```

For concept selection, `afterTurn` is 2 and the digest binds turn 2. Replace
all placeholders with actual evidence. Preserve the review outside actor
work and pass the gate file only to the runner's `--gate` argument. It does
not become an extra user prompt. If advancement is blocked, retain a
disposition and send nothing; do not manufacture an `advance:true` gate.

This checklist was prepared by source reading only. No model, browser,
build or test was launched and no actor or frozen source was mutated.
It adds no instruction to the frozen candidate or actor-visible fixture.

# One bounded browser-only replacement

Prospective protocol, frozen with the replacement binding before execution.
Nothing in this document launches work or grants another retry. Root owns
the approval record, final helper freeze, commands and decisions.

The user approved one replacement browser capture in short batches, with
at most 900,000 ms of total execution and no model call or further retry.
The interrupted `concepts-1` capture and all earlier actor/source evidence
remain immutable. New data and outputs belong only to the separately bound
`concepts-2` replacement. This is still measurement of the 182-file
post-closure recovered source, not a retroactive claim of original turn-2
closure identity or an unmodified frozen comparison.

## Scope stays fixed

Keep the entire unchanged targets document in every batch manifest. The
schedule is exactly its 12 alternatives in declared order. Each batch
selects one exact alternative and captures both original desktop and phone
viewports. It runs its own production build and serves the unchanged saved
source; this is not a reused final-build proof. Each viewport retains the
entry, opening, middle, ending and pointer/keyboard before/after originals.
The full successful coverage is 24 reports and 192 originals. Missing or
broken aliases are not silently discarded as unimportant choices.

Source identity covers the whole reconstructed workspace, including all
siblings of `site/`. The canonical `site/` application path is only the
install/build/server cwd. No actor-source correction, new exclusion or
changed target, expectation, beat, control or observation threshold is
authorized. The prior source-route chooser correction stays explicit and
unchanged. All original assessment functions remain the basis of checking.

## Shared execution budget and no retry

Charge the one fresh setup operation and every batch exactly once. Setup
includes reconstruction and the single recorded offline dependency install.
The charged time is each actual outer recorder's `durationMs`, including
the complete coordinator invocation, child build/browser work and shutdown.
The child lifetime ledger remains independently checked and must not exceed
its containing outer duration. Setup's at-most-90,000 ms and each batch's at-most-90,000 ms
allocation come from the reviewed budget implementation; each allocation
reserves 5,000 ms for shutdown inside its limit. A new operation cannot
start with exhausted budget or an unknown previous closure. Before launch,
reserve the entire next allocation against the sum of prior outer durations,
not just their shorter child durations. Every outer duration must fit its
operation's allocation and their sum must remain at most 900,000 ms.
Coordinator preflight, source checks and closure work inside each recorded
invocation are included. Inter-invocation manual review and the final
read-only audit are excluded; the complete run is not claimed to finish
within 15 minutes of calendar time. Any actual cap overrun fails, even if
attributed to scheduling.

The ledger must include every exclusive attempt, not only successful ones.
Charge actual observed duration without rounding down, clamping or omitting
a failed operation. An interrupted, failed, overrun or incompletely recorded
operation halts the sequence; its directory cannot be reused. Root manually
launches only the next eligible operation. There is no automatic next batch,
background retry, model call, judge call or source repair.

The retained process evidence must distinguish deadline, external signal,
spawn/log failure and actual terminal closure. An unknown signal sender is
not diagnosed by inference. The inherited bounded-process helper signals
its owned child; its hard escalation does not prove every detached
descendant or inherited pipe has closed. Unknown or over-budget closure
therefore cannot pass the ledger or authorize another operation. Shorter
batches are not evidence that the cause of prior external SIGTERM events
has been identified or fixed.

## Independent verification and review

The final read-only verifier must bind the old frozen/amended inputs,
interrupted capture, new replacement/helper hashes and source checkpoint;
replay the complete execution ledger; and compare actual command, limits,
environment, lifecycle, streams, source-before/after and every artifact.
Each batch must contain exactly its selected alternative in both modes,
and the global union must contain all 12 alternatives exactly once.

Original coverage checks apply to every report, including the entry and
both modalities' before/after images. Recompute technical problems from the
raw reports rather than accepting a saved `passed` flag. A complete report
can contain a failed control or unexpected request; completion is not a
technical pass. Nonzero process status cannot become a passing capture.

Review every newly emitted original separately at original detail. The
review inventory must contain exact unique repository-relative paths,
SHA256, byte size and `viewMethod: "view_image original"`, with no omissions
or extra/duplicate paths. Earlier capture images do not count as new review.
All original technical, factual, semantic and visual criteria remain; an
identity change or screenshot difference alone does not prove a meaningful
concept. The verifier reports integrity and technical coverage, not author
approval, a semantic pass or permission to advance the actor.

## Records and root-only commands

The new replacement record has kind `concepts-batched-replacement` and
binds root approval, a new ordinary recovery `binding` pointing to the
unchanged amendment/targets but new `concepts-2` output, the previous
interrupted manifest/recorder result, exact ordered `schedule` and the nine
new `helperHashes`. Its SHA256 is the budget's `bindingSha256`. This is
separate from the original recovery binding and amendment hashes. Original
measurement and runner helper maps remain bound by the unchanged amendment.
`loadReplacement` verifies all of these before an operation.

Output is
`evals/runs/stage-3-completion-2/full-journey-recovery/candidate-2/concepts-2`;
the separate control root is the sibling `batched-control`. Its
`operations/00` is setup and `operations/01` through `operations/12` are
batches. Each exclusive directory retains `attempt.json`, `command.json`,
`process.json`, `closure.json`, `source-before.json`, `source-after.json`,
`stdout.log`, `stderr.log`, `lifecycle.jsonl`, root-authored `supervision.json`,
plus `artifact-inventory.json` for batches. Missing closure blocks advancement. No operation directory
may be reused or overwritten.

After actual normal recorder and tool closure, root exclusively writes:

```text
supervision.json: {result: {path, sha256}, terminal: {path, sha256}}
terminal file: {observedAt, toolResult: exact terminal exec/write_stdin result}
```

The recorder result must be the actual sibling
`candidate-2/batched-command-NN/result.json`. Its four raw artifact hashes,
normal supervisor events, native executable, exact run-operation argv,
repository cwd, frozen install environment with telemetry unset and original
recorder hash are all checked. The terminal observation must follow closure.
Outer child PID must equal the measured coordinator PID. Both scopes must
be normal and the actual child/outer durations and sequential timestamps
must agree. The supervisor cannot be synthesized by the still-running child;
an absent or failed outer terminal record prevents the next operation.

Setup delegates whole-source reconstruction and the recorded offline
install to unchanged frozen helpers, inside its one bounded worker. Its
output records live at `concepts-2/setup/`. Batches write to
`concepts-2/batches/NN/artifacts`, with actual indexed directories such as
`12-desktop` and `12-phone`, not renamed copies of a first alternative.
Each closure binds the exact setup reconstruction/targets/install result,
before/after source, and applicable artifact inventory/manifest hashes.

Root first reviews and commits the replacement helpers, pure tests and
records. Using the exact recorded native Node and frozen install environment
with telemetry unset, the original durable recorder must supervise this
one-operation command. Use the displayed repository-relative argv so it
matches the bound outer command exactly:

```text
node evals/runs/stage-3-completion-2/full-journey-recovery/batched-measurement/run-operation.mjs
  --replacement <repository-relative replacement.json> --id <0..12>
```

Root invokes each eligible ID separately, retaining complete outer tool
launch/poll/terminal evidence and checking owned process closure. There is
no shell loop or automatically launched next operation. ID 0 uses the
original install environment with telemetry unset; capture children use
the original measured environment with telemetry disabled. This is not a
new capability proof or model attempt.

After all operations and all-original review, invoke the read-only verifier:

```text
node evals/runs/stage-3-completion-2/full-journey-recovery/batched-measurement/verify.mjs
  --replacement <repository-relative replacement.json>
  --review <repository-relative all-originals-review.json>
```

The review inventory uses `{schemaVersion:1, complete:true, images:[...]}`
with the exact image fields specified above. A combined inventory may
assemble several reviewers' individually viewed originals, never substitute
contact-sheet viewing for each original. This verifier also checks exact
normal lifecycle events, sequential times and the old interrupted capture's
artifact hashes. It prints a read-only result; root retains that output.
No semantic gate is automatically issued even when `technicalPassed` is true.

The exported pure `assertBatchCoverage` is used by the coordinator closure
and synthetic tests. Tests can exercise omitted/duplicate targets, modes,
images and control records without a browser. They do not count as actual
capture or original-image review. No execution is performed by importing
the verifier, budget or binding modules.

## Idea

Question: **How do you turn an architectural idea into something that can be built?**

The page follows the drawing-set order Marta gave us. One object, six thin drawing sheets, remains present from first to last screen. Each sheet is indexed to a chapter. Their changing arrangements explain relationships: a plan beside a built view, a section beside the structure it describes, a detail beside construction evidence. They return to a complete indexed set at the end.

The opening starts with an actual owned cabin drawing, acknowledging the workshop and timber-joint book in text. No generic spinning building, recreated book page or invented workshop tableau. Meaning comes from real marks and real attribution; the camera does not fly visitors through a simulated property.

The final answer will connect drawings, details and attention on site. Its exact wording is deferred with all captions. This is a personal portfolio for future old-house/small-plot conversations and guest-critic invitations, with current Associate role explicit. It does not announce an operating independent practice.

## Thirty-second visit

### Exact interaction rules

- Chapter links are real URL anchors. Selection moves to the chapter's heading; keyboard focus is managed without trapping the visitor. Deep links open the requested content directly, without replaying the opening sequence.
- Work index items jump to cabin Plans, school Sections and Calder Details. These are separate named anchors, not links to unfinished standalone pages.
- Clicking a drawing or photograph opens an accessible full-size viewer showing its project, author and any approved credit. Viewer provides close, next/previous only when there is a real image sequence, keyboard controls, focus return and touch zoom. Without JavaScript, the same link opens the image file.
- Hover can add a subtle outline or index highlight. No fact, action or credit depends on hover. The scene never requires dragging, clicking a tiny 3D surface or manipulating a camera.
- Both contact choices open the same supplied public email address, with different editable subject lines for a future-project conversation and a guest-critic invitation. Show the address as selectable text too. No invented address or booking availability.
- Credits open a readable HTML list; CV is a real PDF download only once corrected and approved. Until then, omit its link rather than offer a dead control.
- On phone, chapter menu can be opened/closed by button, closes after a choice and has appropriate keyboard/focus behavior. Contact remains reachable without overlapping images or device safe areas.

## Scene behavior and access

| Where | What the visitor gets |
| --- | --- |
| Desktop with WebGL | Text and image evidence remain HTML; six-sheet canvas sits alongside or behind a reserved visual area. Short sticky passages transform the set; pointer interaction is optional. No scroll hijacking, drag requirement, camera spins or idle motion. |
| On a phone | Single-column reading order, images/drawings full width, short scene area between content blocks. If device supports it, shallow sheet fan/rotation; no long pinned sequence. The same indexed set appears in compact states from start to finish. Diagram relationships use stacked image pairs; details open in an accessible zoom viewer. Portrait and landscape layouts; comfortable touch targets; no hover-only content. |
| With reduced motion | Six static arrangements represent the same relationships. No interpolation, parallax or animated assembly. Chapter labels and inline diagrams explain changes. |
| With no WebGL | Static owned-image composites of the six sheets plus ordinary HTML drawings/photos; no error screen, missing proof or blocked contact. |
| With no JavaScript | A complete server-rendered/static HTML page: six chapters, real images, source/role captions, anchor navigation and working email links. Drawing/image links open full-size assets with useful descriptions. |

Use semantic headings, logical reading/focus order, visible keyboard focus, descriptive image alternatives and adjacent explanations for drawings. Canvas is decorative to assistive technology because HTML carries all meaning. Viewer supports Escape, keyboard controls and focus return. Sheet textures cannot be the only place text, credit or evidence exists.

## Look and type

Selected direction: **Workshop paper**. Colour is quiet so drawings, graphite and timber photographs supply the richness. Technical information is readable, not tiny decorative microtype. Large type comes from hierarchy and space, not giant words obscuring work.

Three possible treatments, kept as planning alternatives; no switcher or prototype is built:

| Look | Ground | Ink | Accent | Sheet surface |
| --- | --- | --- | --- | --- |
| Workshop paper — chosen | Warm off-white #F3F0E8 | Graphite #242824 | Oxide #914D35 | Matte cream, fine edge/shadow; original drawing texture retained |
| Tracing desk | Neutral chalk #F6F6F2 | Charcoal #202622 | Deep green #365548 | Pale drafting-paper sheets; subtle translucency only where legibility survives |
| Site notebook | Warm stone #E8E3D9 | Near-black #222321 | Timber brown #75543A | Slightly heavier stock; restrained warm edges, no fake weathering |

Accents serve links, active chapter and annotations; text contrast must be checked in implementation, especially over photos. Timber is an image/material cue, not a generic wood-textured page background. No blueprint-blue wash or invented handwritten notes.

Two typefaces: **IBM Plex Sans** for headings and body; **IBM Plex Mono** for sheet identifiers, scales when genuinely documented, credits and register labels. Self-host only needed styles after license verification. Body roughly 18–20px desktop and 16–18px phone; comfortable line height, 55–70-character reading width. Large headings resize fluidly. Mono never becomes the long-body typeface. Use accurate original drawing lettering within images rather than replacing it with invented text.

## The thread

A bound runbook opens into the library where Dawit came to software. Its leaves bend into a route, support a reading stand, open into working documents and raise five different work miniatures. At the close those fold into one complete book with a contact invitation and CV leaf. The binding and paper behaviour connect the chapters; the scene subjects change with the story. No repeated wall of project cards, decorative server racks or anonymous points-as-data.

The opening begins with Dawit's library work and the 2014 outage account. The closing brings the runbook, cutover checklist and rollback plan together, recalling the confirmed reason he cares about rollbacks. There is no rhetorical question or implied promise of incident-free migrations. The complete book is a visual ending, not a claim that the 2014 table or a real system was restored.

All geometry is an illustration, visibly labelled. No photographs, screenshots, copied covers, actual employer diagrams, slide reproductions, actual runbook text or actual commands. No assets to acquire or additional skills to install.

## The first thirty seconds

The first screen carries Dawit's name, a plain-language description of migration work as moving or changing systems, and one proof: the runbook first version/continuing ownership and its use by 40 teams. The everyday meaning of cutover (changing which system is in use) and rollback (a way to return to an earlier state) is provided where those terms first appear; these are generic explanations, not promises about real systems. Avoid the unconfirmed formal role title.

The catalogue/library origin is pictured immediately; the 2014 account gets the next short beat rather than occupying the whole first screen. A visible contact shortcut, CV link and chapter navigation make the site usable without following the scroll. On phone, reserve enough initial space for name, work and proof; geometry scales down before those move out of view. The concept sketch's generous mobile illustration height is not a requirement to preserve in the final opening.

## Navigation and five detail pages

Normal document scrolling; no scroll hijacking, forced progression, scroll lock or required gesture. Stable heading IDs and URLs. Desktop shows all seven chapter links; phone uses an ordinary HTML disclosure for those links plus an always-visible contact shortcut. A skip link goes to contact. Focus indicators, usable tap targets and labels for every control; no canvas-only interaction.

Project summaries are present in HTML on their corresponding beats. Each opens a separate local page in the same tab, with a meaningful URL, one h1, a back-to-projects link and the same contact/CV access. This gives usable browser Back, deep links, keyboard navigation and no-JavaScript behaviour without modal complexity. Decorative scene objects do not need to be clickable; adjacent HTML links are authoritative.

## Without the scene

All substantive text, navigation, work links and contact/CV remain ordinary server-rendered HTML. The scene is an enhancement with an accessible label, not a reading surface or source of exclusive facts.

| Case | Visitor experience |
|---|---|
| Phone | Compact scene above flowing text; chapter-specific static/framed composition; no text overlay on moving objects. Normal scrolling, responsive line lengths, touch-friendly controls and all five work links. Geometry and pixel density reduced before text is compromised |
| Reduced motion | Discrete scene poses at beat boundaries; no fly-through, continuous curl, idle motion or automatic token travel. Model state can change through explicit buttons, without animated interpolation. All content and controls remain available |
| No WebGL, context loss or a failed scene/chapter | Labelled local static illustrations beside the same HTML, plus normal navigation. A scene failure is contained; it cannot remove the text, links or other chapters. No repeated error notices competing with the story |
| No JavaScript | The entire story, detail pages, CV/download, ordinary disclosure navigation and mailto render as HTML. Static locally generated illustrations stand in for 3D; no animated spacing gaps, loading spinner or essential hidden disclosure |
| Paused illustration | A plain pause/enable-3D control can choose static illustrations while retaining document scroll. It never disables navigation or text. Offscreen rendering pauses automatically |

Static alternatives will be locally generated drawings of the same subjects, sized explicitly with useful alt text. No actual employer topology in either 3D or static form. Purely decorative geometry is hidden from assistive technology; controls and explanations remain in HTML.

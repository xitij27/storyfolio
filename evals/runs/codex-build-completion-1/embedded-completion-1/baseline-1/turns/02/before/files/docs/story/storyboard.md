## Governing idea

**How does a firmware decision become a measurable signal?** A state table
becomes a responsibility table, an explanatory diagram and an evidence
ledger, then returns to a complete table. Six persistent matte row cards
carry the story. They are narrative pieces, not six firmware states or six
physical boards. This is a card-engine fixture, not a non-sheet proof.

The audience is a firmware hiring manager. State Ada's contribution and
its limits clearly in HTML. The scene supplements that text. The colleague's
PCB/analogue contribution stays distinct from Ada's firmware, scheduling
and fixture work; measured inputs, projected endurance and unfinished
qualification stay distinct from one another.

## Static modes and accessibility

At widths of 767 CSS pixels or less, use a single-column static page with
chapter anchors and large readable supplied diagrams. Do not mount or
download a scene-only/WebGL chunk to read this mode. At wider widths with
reduced-motion preference, use the same static content with no scene
canvas or scroll-driven movement. These are explicit fixture choices that
override the engine's default mobile and reduced-motion animation behavior.

No JavaScript, unavailable WebGL and a renderer failure all retain the
complete seven-beat HTML, diagrams, navigation, email and CV. A CSS-hidden
or invisible animated canvas is not the chosen static mode. A desktop
without those constraints must have the intended scene.

There is one h1 and unique IDs for both Observation beats. Meaning is not
encoded by color alone. Images have the alternative text recorded in
`assets.md`, diagram descriptions are ordinary HTML, links work with the
keyboard and focus remains visible. A simple link to each SVG is the
approved keyboard-operable expansion; no dialog or complex zoom is needed.

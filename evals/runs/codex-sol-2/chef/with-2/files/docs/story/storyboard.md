## Direction

Question: What happens before the menu is written?

Form: Ines's ferment log, using Started, Salt, Check days and Ready as chapter anchors. An opening index and closing Next entry are editorial framing. This does not purport to reproduce the real log's layout or contain a single actual batch record.

One object: eight designed paper log sheets. Each has a stable identity and source-backed content: identity/larder; career context; prep-list process; log fields; kitchen measurement; Brine; Sunday Pot and workshops; final menu-order diagram/contact. The last sheet represents the fact that the menu is written last, not an invented menu. There are no fictitious dish names, salt percentages, recipes or check dates. All sheets remain in the scene through every chapter; inactive sheets rest at its edge, never obstructing HTML text. No continuous idle spin, flying ingredients, jar-opening tricks or unexplained colour-changing ferments.

Meaningful depth comes from sheets exposing the document sequence and relationships. Images can appear as textures, but every meaningful word, image description, number and link also exists in HTML. The graphic is supplementary and non-interactive; text links carry the controls.

## Phone, access and failure states

| Situation | What the visitor gets |
|---|---|
| Phone | One-column HTML story; static sheet images adjacent to their content; chronology expands inline; horizontally wrapped chapter links; generous touch targets. No pinned full-screen camera sequence or sideways swiping requirement. Optional subtle fades only when motion is allowed. |
| Reduced motion | Same chapters and evidence; a static folio plus chapter-specific static diagrams; no parallax, interpolation, zoom, automated fades or camera travel. Anchor jumps are immediate. |
| No WebGL or failed/context-lost canvas | Static sheet/diagram images with the same content. No modal error or blocked contact links. |
| No JavaScript | Server-rendered or static HTML, native anchors/details, images and email links. All chapters remain visible. No form depends on JavaScript. |

Keyboard navigation, visible focus, logical headings, descriptive links, alt text and sufficient contrast are build requirements. Canvas is decorative to assistive technology because all its semantic content is duplicated in the document. Text is never rasterized as the only readable version. Test at 320 CSS pixels and with enlarged text; no content depends on hover. If a real log sample is too small to read, provide its text transcription.

Selected look is design judgment, not a claim about the kitchen's actual stationery. Texture is restrained; no invented handwritten annotations, dirt or faux archival history.

Two typefaces: Source Serif 4 for editorial text and headings; IBM Plex Mono for log faces, field labels, dates and small navigation. Both can be self-hosted with their open font licences retained. Use regular/medium weights, comfortable line spacing and about 60–70 characters per desktop text line. On phones use at least 17px body text; no huge title forcing the proof or contact off-screen. Green communicates emphasis, never the sole meaning of a status. Verify actual foreground/background pairs for contrast in implementation. Alternatives are documented options for review; no palette selector is required.

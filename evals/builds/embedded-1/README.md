# Embedded build fixture 1

This is a new, explicitly fictional derivative of Ada Mensah's saved
`codex-opening-1/embedded/with-2` planning conversation. It is a bounded
build fixture for stops 4 to 6, using that conversation's six row cards.
It is a card-engine regression case, not proof of a non-sheet object,
concept-stage sketching, before-stop-1 behavior, or a complete six-stop
journey. No model conversation has been run for this fixture yet.

The author approved the extracted engine after desktop and physical-phone
review on 11 October 2026. That real approval allows preparation of this
experiment; it is not approval of a new fictional person's storyboard or
site. The fictional confirmations under `workspace/docs/story/` are
coordinator-authored evaluation data, not statements from the real author
or from a real Ada Mensah.

## Files and ownership

- `workspace/` is the actor's starting material before the engine is
  scaffolded. It has no existing application, package manifest or lockfile.
- `expectations.json` belongs to the coordinator. Freeze and use this
  external copy for acceptance checks; the actor must not edit the source
  of its own expected results.
- `workspace-inventory.json` records the starting files and their hashes.
  Preparation must also retain the actual before-scaffold inventory and
  tell the actor which files were supplied and which were scaffolded.
- `source-manifest.json` records unchanged historical inputs and hashes
  the allowlisted starting fixture artifacts, including the authored SVGs
  and accessible CV. It excludes itself to avoid recursive hashing; the
  runner freezes case configuration and protocol separately.

The prepared run must record the actual Node/git/browser versions and
enabled/disabled skill inventory. This fixture cannot truthfully claim
those machine properties in advance. The engine requires Node 22.18 or
later with native TypeScript support. A harness preflight is useful setup,
but is not evidence that the actor checked the machine itself.

`evals/people/embedded/` and
`evals/runs/codex-opening-1/embedded/with-2/`. The source manifest identifies
each input. The saved run stopped at storyboard review, with building
explicitly excluded. This derivative deliberately supplies a new fictional
approval and build request instead of treating the historical selection as
approval. The protocol must give the same external continuation contract
to both arms while retaining the planning-only skill for the baseline.

The complete changes from that historical scope are:

## Acceptance and limits

The independent checker reads `expectations.json` from the coordinator's
frozen copy. It checks seven beat IDs, readable factual text, local assets,
links and declared fallback modes. Browser evidence must cover every beat,
deep links, keyboard focus, the three looks, reduced motion, no JavaScript,
no WebGL and a missing route. Human review still assesses prose, diagram
legibility, framing, choreography and factual implications. A passing
substring check is not proof that no contradictory text appears elsewhere.

`docs/story/decided-for-you.md` gives all eleven checklist decisions.
`docs/story/assets.md` lists provenance, purpose, limitations, terms and
alternative text for every supplied visual. Public files and the CV are
fictional evaluation assets released under the repository's MIT license.
No external skill is supplied or installed. Review of third-party skill
sources and dated commands is separate coordinator evidence; without it,
source/command verification must remain unobserved. This fixture alone
cannot evaluate successful use of installed complementary skills.

Engine scaffolding and locked dependency installation are preparation,
not actor work. Record both without attributing them to the actor. The
actor should be able to discover that the original folder contained only
story documents, material and public assets. Stop-4 startup observations
do not establish that those checks happened before stop 1.

A scripted fictional choice of look or copy advances the model
conversation. A scripted final approval supplies no real desktop or phone
test. The repository author's eventual review of the built result remains
a separate, real gate, and no publishing is authorized by this fixture.

## Fixture verification

Run `node evals/builds/embedded-1/verify-fixture.mjs` from the repository.
It compares all 19 historical input files with commit
`da3c20238d5dc840328753aa0ac4ff5abc53a740`, verifies the source and asset
inventory, required wording, shared ID namespace, links and checklist
coverage, and checks the frozen hashes. It does not test an implemented
site. `--refresh` rewrites fixture hashes only after the historical-source
comparison and content checks pass; never refresh a frozen paid run's
inputs. The runner must freeze the exact manifest used by each run.

[Verification notes](validation.md) retain the initial sandbox limitation
and successful local checks. [SVG structure results](asset-structure-check.json)
record XML validity, dimensions and local references; those checks do not
replace rendered visual review of the eventual site.

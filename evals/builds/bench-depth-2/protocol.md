# Bounded Stage 3 visual comparison

Prepared 12 October 2026. The author's direction is to finish Stage 3 first.
The separate bounded paid-comparison question is awaiting an answer when
this protocol is written. Preparation does not permit launching models.

## Question and fixed conditions

Does carrying the approved scene meaning and readable transitions through
build review improve the five-beat apparatus, without changing its story,
engine, supplied capabilities or factual boundaries?

Use one fresh unchanged-skill baseline under `codex-bench-depth-baseline-2`,
then at most one separately labelled candidate under
`codex-bench-depth-candidate-1`, only if the reviewed baseline supports the
candidate. Each is one fresh actor turn, with at most one text judge after
complete-packet preflight. The actor deadline is 15 minutes; each judge's
deadline is 10 minutes. No continuation or automatic retry. These are
process-time limits, not hard token or dollar caps. Record actual usage.
If the relevant visual criteria already pass, omit redundant instructions
and do not spend a candidate run without a remaining specific question.

Both arms receive the exact same original fixed actor request, rubric,
nine fixture files, engine, dependency lock, capability configuration,
enabled-skill facts, neutral helper, checker and expectations. Freeze their
hashes before the baseline. Only a reviewed skill candidate may differ.
Candidate placement and changed paths must be explicit in its input diff.
The old baseline is not relabelled or reused as the unchanged-condition arm.

The fixture's `evaluation-environment.md` makes the supplied tools visible
and fixes the inherited skip navigation for prospective measurement.
Neither accepted implementation nor earlier actor source, recovery design,
rubric or original screenshots enter the actor workspace. Audit actual
reads. Configuration isolation alone cannot prove inaccessible held-out
files; a held-out solution read invalidates an independent-build claim.

## Candidate selection

The [evidence audit](../../runs/stage-3-integration-1/evidence-audit.md) contains
two draft visual paragraphs supported by the earlier composition/detail
and transition failures. Review the new baseline before choosing either.
Do not add facts, a prescribed apparatus, arrows, palettes, piece counts,
engine mechanisms, mandatory controls or six unused reference files.

The shipped skill still ends at the storyboard. The same explicit build
override remains in both task requests. Do not add ordinary build-entry
routing on the strength of this diagnostic. Any candidate location must
be read in the actual task and preserve planning-only behavior. A later
planning regression remains required before a shipped capability claim.

## Assessment and stopping conditions

Keep technical checks, text judgement, source-bound visual review and
actual author approval separate. Review original images of all five rests,
forward/reverse travel, phone/short views, reduced motion and failure modes.
Use the existing Backdrop, Depth, Swap, Detail/hierarchy, Spatial and
Phone/still criteria without tuning them after a candidate is seen.
Preserve factual ownership and projected-versus-observed evidence limits.

The complete input/source/artifact inventory must verify. Capture source
before and after; unknown new runtime paths must not be discarded as Git
metadata. Reject altered or incomplete judge evidence instead of trimming
it. A failed command or time-limited result stays in its own cohort.
Do not convert corrected measurement into historical acceptance.

End this milestone with the two actual results, or with the baseline alone
if it passes the question or cannot support a valid comparison. Passing
this diagnostic is not Stage 3 completion. Natural build entry, early
machine/sketch coverage, actual choice gates, integrated finish, planning
regression and the approved non-sheet whole-site proof remain.

# Prototype-depth diagnostic protocol, version 1

11 October 2026. Local preparation under the
[reproduction plan](../../../docs/superpowers/plans/2026-10-11-build-workflow-reproduction.md).
This protocol is evaluator-only. Its configuration describes a proposed
paid envelope, not permission to invoke it.

## Question and fixed inputs

Can one fresh agent, using the unchanged planning skill, supplied engine
and approved meanings, implement a convincing five-beat, object-led
prototype without seeing the accepted solution? The actor chooses the
composition; the non-sheet object premise and approved story are supplied.
This tests implementation, not profile-to-story discovery, automatic skill
activation or the eventual supported build entry point.

Freeze schema-2 case `bench-depth-1`, the one actor prompt, fixture
allowlist, expectations, this protocol, criteria, source manifests,
unchanged skill/engine, lockfile, runner, checker/capture and judge code.
The runner's input digest is the final identity, not this prospective date.
Commit these before preparation. Use a fresh external workspace and the
loopback-only capability profile, preserving initial inventory, actual CLI
capabilities and enabled/disabled skill state. No paid call is needed to
verify setup. Harness setup and probes do not establish actor preflight.

Do not execute before the known engine issues and complete judge-transport
question have an explicit disposition. If a shared engineering fix is
required, review it and freeze a common engine before either arm. Never
attribute a changed engine, fixture or measurement to a skill-only effect.

## Information boundary and audit

Actor input is exactly the case's seven workspace files, the unchanged
skill and engine, technical documentation, and factual setup information.
No accepted source/screenshots/exact copy/geometry/poses/styles, recovery
specification revealing the solution, prior actor output or rejection
review may be copied into that workspace. The rubric, expectations and
this protocol stay coordinator-only. Do not disclose repository paths to
held-out material in the actor request or story documents.

The capability profile isolates configuration, not filesystem reads.
Review the saved commands and output for repository/prior-run access,
including held-out files reached indirectly. Record explicit contamination
and mark independent reproduction invalid. Absence of logged reads does
not establish a read jail or prove that missing telemetry was harmless.

## Assess four distinct results

1. Technical acceptance: independent coordinator build/type/lint checks,
   five frozen beat IDs and heading structure, seven browser conditions,
   pointer/keyboard operation, all rests, forward/reverse travel samples,
   stillness and post-context-loss coverage. Actor-authored checks are
   separate evidence. Passing structure is not semantic or visual approval.
2. Behavior: the text judge applies `criteria.md` only to complete supplied
   evidence. Pixel quality remains unobserved. Preserve full tool failures,
   source and acceptance reports. Apply both 2 MiB UTF-8 and 1,048,576
   UTF-16 code-unit guards before spending a judge attempt. No truncation,
   inferred file contents or improvised reduced brief. An accessor would
   require a separate transport decision; none is presumed available.
3. Visual review: review original images, not only contact sheets, bound
   to source hashes, conditions and actual positions. Capture desktop
   1440 by 900, phone 390 by 844, short 1280 by 720, reduced motion, no
   WebGL, no JavaScript and actual context loss. Observe all five rests
   and four transitions in both directions. Exercise every implemented
   control by pointer and keyboard without prescribing four controls.
4. Author assessment: new output needs its own approval and physical-phone
   report. Acceptance of the manual reference supplies neither.

Each criterion is pass, fail or unobserved with original evidence.
Record artifact completeness, environmental limits, packet validity and
contamination separately. Do not hide an unsupported claim or missing beat
in an average score. A partial artifact caused by a deadline is not alone
an instruction defect. Missing image-view events do not prove skipped
image review, and a text judge must not claim pixel observations.

## Visual questions, independent of the accepted design

| Criterion | Observation |
|---|---|
| Backdrop | The object explains a work relationship or presents useful evidence rather than merely repeating headings. Accessible HTML remains present. |
| Depth | All five beats add their distinct meanings and lead to a supported answer; section count alone is insufficient. |
| Swap | Object and behavior are specific to this work rather than a generic scene with renamed labels. |
| Detail and hierarchy | Important artifacts are inspectable; details aid understanding without crowding reading or controls. |
| Spatial quality | One recognizable object changes meaningfully; composition, movement and occlusion serve explanation. |
| Phone and still modes | A narrow viewport retains meaningful visual treatment, and reduced-motion/failure modes retain complete accessible meanings. |

Factual ownership, provenance and evidence boundaries are mandatory in all
modes. Do not count effects, require a fixed printing technique, prescribe
four pieces, match a palette, force all engine hooks or pixel-match the
accepted reference. Sampled motion is not an every-frame or frame-rate
guarantee. Known-positive/negative calibration on retained original studies
is a sanity check, not blind validation or general scoring accuracy.

## Attribution and next decision

Assign each actual miss to behavior, source ambiguity, fixture constraint,
engine, environment or measurement before proposing an instruction. A pass
adds no redundant skill prose. A failure-backed instruction needs a new
approval for a matched rerun with all other frozen inputs held fixed.
Changing those inputs creates a new baseline, not a causal before/after.
Stops 4/5/6, full journey, non-sheet generality, earlier preflight timing,
activation, concept sketches, wording choices and packaging remain outside
this diagnostic. No publication or push follows from preparation.

# Bench-depth prototype fixture

This new fictional derivative tests realization of five approved story
meanings with the unchanged Storyfolio skill and engine. It is a
`prototype-depth` diagnostic, not a request for stop 4, 5 or 6 and not
proof of the full six-stop journey. The author authorized local preparation
only. No paid actor/judge call, skill change or push is authorized by this
fixture. The [protocol](protocol.md) controls the separate execution gate.

## Boundary

Only the seven explicitly allowlisted files in `workspace/` are supplied
as fictional story input. The runner separately supplies the unchanged
planning skill, engine technical documentation and factual setup evidence.
The initial folder has no app or package manifest. Actual machine and
pre-scaffold observations must be captured during preparation; the static
inventory is not an actor preflight.

The actor gets corrected facts, a new fictional confirmation, five ordered
beat meanings and two unchanged illustrative SVGs. It does not get old
row-card constraints, disputed original CV wording, the unapproved incident
note, accepted implementation, exact copy, geometry, poses, colors,
screenshots, previous actor output, visual-recovery specs or reviews. The
supplied diagrams are teaching assets, not a composition or four-piece
prescription. Their source and limitations are retained in the fixture.

`expectations.json`, this README, the source manifest, protocol, prompt,
criteria and verification code are coordinator-owned, not actor files.
They are frozen independently by the runner. In particular the accepted
reference is a reviewer calibration source, not an actor input or a
pixel-match target. Configuration isolation is not a filesystem read jail;
saved commands/output must be audited for held-out access after execution.
Contamination invalidates an independent-reproduction claim.

## Contract and limits

Schema 2 freezes ordered beat IDs and structural heading levels, but no
headings or exact public sentences. Semantic obligations remain separate
from substring checks and require factual/source review. Normal desktop,
phone and short modes require the 3D scene, which is a diagnostic technical
requirement, not a biographical fact. Reduced motion retains the engine's
still scene, with stationary captures; failure modes preserve complete
explanations. No exact control count, palette, camera, geometry,
duration or piece count is prescribed.

One appearance excludes stop 4's multiple implemented looks and selection.
No stop 5 copy-choice gate or stop 6 full-site checklist is requested.
Explicit invocation does not test activation; a supplied approved story
does not test concept discovery. An opening refusal of optional-skill
installation does not test a later recommendation-then-refusal branch.
No source packet verifies any optional skill's source or install command.

The text judge sees complete text/source/tool evidence when transport
permits, not screenshot pixels. Technical acceptance, behavioral judgment,
original-image review and actual author approval remain separate. The
author's acceptance of a previous manual prototype approves no new output.

## Local verification

Run `node evals/builds/bench-depth-1/verify-fixture.mjs`. It checks the
allowlist and starting inventory, exact retained source hashes, unchanged
SVG bytes, verbatim actor request, neutral five-beat expectations and the
case schema. This is a deterministic fixture check, not a website or model
run. It never refreshes a manifest or changes historical artifacts.

The runner's no-model `--dry` and `--prepare` paths follow successful
integration checks and a committed final input freeze. They do not
authorize `--turn 1`. Final engine-risk and judge-transport disposition,
exact environment proof and a specific paid-run decision are prerequisites
to launch. Follow the saved preparation evidence for current blockers.
